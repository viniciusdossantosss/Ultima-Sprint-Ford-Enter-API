O Problema que Resolvemos
Academias e escolas de natação enfrentam desafios diários na gestão manual de aulas e agendamentos.
📋
Overbooking de Vagas
Controle manual de vagas gera risco constante de lotação e insatisfação dos alunos.
⏰
Conflitos de Horário
Sem detecção automática, alunos e professores frequentemente enfrentam sobreposições de aulas.
👥
Falta de Segregação
Sem distinção clara entre perfis de professor e aluno, gerando confusão de permissões.
📜
Sem Histórico
Impossível rastrear agendamentos, cancelamentos e padrões de uso sem sistema digital.
AquaSchedule — A Solução
Uma API RESTful moderna e completa para digitalizar toda a gestão de aulas de natação, do agendamento ao controle de capacidade.
🔗
API RESTful Completa
Endpoints padronizados seguindo REST para gestão de turmas, reservas e autenticação de usuários.
📊
Controle de Capacidade em Tempo Real
Cálculo dinâmico de vagas disponíveis, impedindo overbooking automaticamente.
🔍
Detecção de Conflitos de Horário
Algoritmo de sobreposição temporal que garante agendamentos sem colisão.
🔐
Autenticação JWT Segura
Sistema robusto com tokens JWT, hash BCrypt e controle de acesso baseado em roles.

🔐 Autenticação e Segurança
Sistema de autenticação robusto com múltiplas camadas de proteção.
  • ✦Registro com validação de e-mail único (RF005)
  • ✦Login JWT com claims: Id, Email, Nome, Role — 8h de expiração
  • ✦Hash BCrypt com work factor 12
  • ✦3 roles: Admin, Professor, Aluno
  • ✦Account Lockout: 5 tentativas → 15 min de bloqueio
  • ✦Rate Limiting: 5 req/min nos endpoints de auth
  • ✦Reset de senha via token com expiração de 30 min

📅 Agendamento de Reservas
Criação de reservas com validação automática de múltiplas regras de negócio.
Validações Automáticas
  • 🛑RF001 — Controle de capacidade máxima
  • ⏱️RF002 — Conflito de horário (sobreposição)
  • 🚫RF008 — Reserva duplicada na mesma turma
Cancelamento
RF009 — Soft Delete preservando histórico. O registro não é removido, apenas marcado como cancelado.
Segregação por Perfil
Aluno Vê apenas suas reservas
Professor Vê reservas das suas turmas
Admin Acesso total a todas as reservas
ALGORITMO DE SOBREPOSIÇÃO
InicioA < FimB && InicioB < FimA
⚙️ Regras de Negócio
13 regras documentadas garantem a integridade e consistência do sistema.
RF001
Controle de Capacidade
Retorna HTTP 400 se exceder o máximo de alunos da turma.
RF002
Conflito de Horário
InicioA < FimB && InicioB < FimA — impede sobreposição temporal.
RF004
Segregação de Perfis
Cada role acessa somente os dados pertinentes ao seu perfil.
RF005
Unicidade de E-mail
Dupla camada: validação na API + constraint UNIQUE no banco.
RF009
Soft Delete
Cancelamentos preservam histórico via flag, sem remoção física.
RF011
Identidade via Token
ID do usuário extraído do JWT — nunca via body do request.
RF012
Integridade Referencial
Restrict para proteger entidades referenciadas e Cascade para exclusões em cadeia quando apropriado.
🛡️ Camadas de Segurança
Múltiplas camadas de proteção para um sistema robusto em produção.
🔑JWT HMAC-SHA256 com zero clock skew para validação precisa de tokens
🔒BCrypt (work factor 12) para hash seguro de senhas
👑RBAC hierárquico: Admin > Professor > Aluno
🚪Account Lockout: 5 falhas consecutivas → 15 min de bloqueio
⏱️Rate Limiting (fixed-window) para prevenção de brute force
🌐CORS restritivo — apenas origens autorizadas
📦Limite de 10 MB por request (anti-DoS)
🚫Tratamento de erros sem vazamento de stack trace
🔐HTTPS obrigatório em ambiente de produção
🩹CVE-2026-32933 mitigada — Mapster substitui AutoMapper vulnerável
